# NLP-модуль запроса: опечатки, ключевые слова, синонимы (v2)

Превращает название закупки в взвешенный поисковый запрос для подбора поставщиков.
Работает **офлайн**, без нейросетевых API (ограничение хакатона).
Зависимости: `pandas`, `rapidfuzz`, `pymorphy3`, `pymorphy3-dicts-ru` (+ `pytest`).

```
nlp/tokenize.py               общий токенизатор (не менялся)
nlp/speller.py                раскладка, опечатки, бренды, леммы с учётом контекста
nlp/keywords.py               предмет закупки, тип (товар/работа/услуга), веса слов     NEW
nlp/synonyms.py               синонимы / аббревиатуры / общее↔узкое                       NEW
nlp/query.py                  process_query() — единая точка входа                        NEW
scripts/build_vocab.py        частотный словарь (как было)
scripts/build_lemma_freq.py   частоты лемм из vocab.json -> веса IDF                      NEW
scripts/mine_synonyms.py      из датасета: «расшифровка (АББР)» + лемма -> ОКПД2          NEW
data/nlp/vocab.json           словоформы (как было)
data/nlp/lemma_freq.json      леммы (собрано)                                              NEW
data/nlp/synonyms_curated.json ручной словарь: 149 групп + 25 «общее -> узкое»             NEW
tests/test_speller.py         старые тесты (21, все проходят без изменений)
tests/test_query.py           новые тесты (41)
```

## Быстрый старт

```bash
python scripts/build_vocab.py        # если vocab.json ещё нет (нужен data/raw/*.csv)
python scripts/build_lemma_freq.py   # ~10 с, датасет не нужен
python scripts/mine_synonyms.py      # ~1–3 мин, нужен data/raw/*.csv  (опционально, но рекомендую)
python -m pytest tests/ -q           # 62 passed
python -m nlp.query "Поставка картриджы для мфу hp для нужд ГБОУ школа № 548"
```

```python
from nlp.query import process_query
r = process_query("Поставка картриджы для мфу hp для нужд ГБОУ школа № 548")
r["procurement_type"]  # 'товар'
r["search_terms"]      # {'картридж': 0.372, 'hp': 0.356, 'расходник': 0.279, 'мфу': 0.26,
                       #  'тонер-картридж': 0.229, 'оргтехника': 0.227, 'принтер': 0.22, ...}
r["explain"]           # ['исправлено «картриджы» → «картридж» (опечатка)',
                       #  'тип закупки: товар — «поставка» в названии',
                       #  'не учитываем «для нужд гбоу школа 548» — заказчик/адрес/срок',
                       #  'предмет закупки: картридж',
                       #  '«мфу» также ищем как: многофункциональное устройство, ...']
r["okpd2_hints"]       # [{'code': '20.59', 'score': 0.87, 'by': ['картридж', 'hp']}, ...]
                       # (появляется после scripts/mine_synonyms.py)
```

Поля ответа: `original, corrected, was_corrected, changes[{from,to,reason}], tokens, lemmas,
procurement_type, keywords[{token,lemma,pos,role,idf,weight}], phrases, synonyms[{matched,term,
kind,source,weight}], search_terms{лемма: вес}, okpd2_hints, explain[], elapsed_ms`.

`correct_query()` из v1 сохранён с тем же форматом ответа — код, который его уже вызывает, не сломается.

### Как подключить к поиску поставщиков

1. Профиль поставщика = леммы `product_name` (ТРУ) и `subject` (Извещения) всех лотов, где он
   участвовал (`Поставщики.lot_id`), победы — с бо́льшим весом. Лемматизировать **той же**
   функцией `lemmatize_tokens(tokenize(text))` + `canon_token` (иначе «a4» латиницей в данных
   не совпадёт с «а4» в запросе).
2. Скоринг: BM25 по профилям, где вес термина запроса = `search_terms[lemma]`.
3. Фильтр/буст по `okpd2_hints`: поставщики, уже поставлявшие этот класс ОКПД2.
4. В карточке поставщика показывать `explain` + какие термины совпали — это критерий
   «Объяснимость» (10 баллов).

## Ревью v1: что было не так и что исправлено

| # | Проблема в v1 | Пример | v2 |
|---|---|---|---|
| 1 | Раскладка исправлялась **после** токенизации, а токенизатор выкидывает `; , . [ ] ' < >` — это русские **ж б ю х ъ э Б Ю** | `ve;crjq` → `ve crjq` | раскладка чинится в сыром тексте до токенизации: «мужской костюм», «поставка бумаги» |
| 2 | «Окно ±12 по fuzz.ratio, затем самое частое» выбирает самую частую **словоформу**, а не ближайшую | `ноутбк` → «ноутбука», `ремнт` → «ремонту» | стоимость = расстояние Дамерау–Левенштейна − 0.35·log10(частота); лимит правок по длине слова (1/2/3) |
| 3 | Правильные слова, которых нет в словаре закупок, «исправлялись» | `снегоуборка` → «снегоуборщика» | слово из словаря OpenCorpora (`word_is_known`) не трогаем |
| 4 | Бренды кириллицей превращались в мусор | `леново` → «легковой» | словарь брендов (57) + латинский бренд в русской раскладке (`сфтщт` → canon) |
| 5 | Латиница вместо кириллицы в характеристиках | `a4` (лат.) ≠ `а4` | гомоглифы и раскладка для токенов с цифрами: `a4`, `f4` → `а4` |
| 6 | pymorphy угадывает лемму незнакомых слов по окончанию | `скуд` → «скуда», `клининг` → «клининга» | для незнакомых слов лемма = само слово, если оно так встречается в данных |
| 7 | Лемма без контекста | `горячего питания` → «горячее» (сущ.) | прилагательное, согласованное со следующим существительным: «горячий питание» |
| 8 | В README обещаны синонимы и ключевые слова — **их не было** | — | `synonyms.py`, `keywords.py`, `query.py` |

Скорость: 100 разных запросов через `process_query` — < 0.1 с (тест: лимит 2 с);
холодный старт (словарь + pymorphy3) ~0.4 с.

## Как устроены ключевые слова

Название закупки = «действие + предмет + для кого + где/когда». Нужен только предмет.

1. Обрезаем хвост заказчика с маркера: `для нужд`, `по адресу`, `для ГБОУ…`, `в 2025 году`,
   `в соответствии с`… (только если до маркера уже есть содержательные слова).
2. Выкидываем процедурные слова (поставка, оказание, услуга, выполнение…), оргформы
   (ГБОУ, ГБУЗ, СПб…), 18 районов СПб, адресные сокращения, месяцы, годы, голые номера.
3. Роли и веса (`вес = IDF леммы × множитель роли`): `head`/`object` ×1.3 (главное
   существительное / предмет действия: ремонт **кровли**), `noun` ×1.0, `brand` ×1.0,
   `spec` ×0.9 («5 мл», «аи-95»), `action` ×0.8 (ремонт, вывоз), `purpose` ×0.7
   (картридж для **принтера**), `attr` ×0.7.
4. Тип закупки: по процедурным словам → по слову-действию (ремонт → работа, вывоз → услуга)
   → по умолчанию товар.

## Синонимы

* `data/nlp/synonyms_curated.json` — 149 групп: аббревиатуры (ТКО/ТБО, СКУД, АПС, СОУЭ, ГСМ,
  ИБП, ПИР, СИЗ, ДПО…), канцелярит ↔ разговорное (клининг ↔ уборка, медикаменты ↔
  лекарственные препараты), и 25 связей «общее → узкое» (оргтехника → принтер, МФУ…; одежда, обувь, спецодежда, школьная форма, шины).
  Узкие понятия расширяются и вверх: «шприц» → «медицинские расходные материалы».
  Редактировать может кто угодно в команде: фразы пишутся в любой форме.
* `data/nlp/synonyms_mined.json` — генерирует `scripts/mine_synonyms.py` из датасета
  по шаблону «системы контроля и управления доступом (СКУД)». Подхватывается автоматически.
* Синонимы ищутся только в «предмете» (не в «ГБОУ школа»), по леммам, длинные фразы первыми.
  Вес синонима всегда меньше веса исходного слова: synonym 0.85, из данных 0.75,
  узкое 0.5, общее 0.4.
