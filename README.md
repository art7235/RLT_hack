# Подбор поставщиков для АИС ГЗ и Электронного магазина СПб

Пользователь вводит название закупки и получает ранжированный список контрагентов:
- **из истории закупок 2024–2025** (604 тыс. лотов, 44 тыс. поставщиков), с объяснением, почему каждый рекомендован;
- **новые компании** из реестра МСП ФНС, которых нет в истории, но профиль деятельности совпадает с закупкой.

Каждому контрагенту присваивается **статус** (проверенный / с опытом / участник / профильный / новый) и **роль**
(производитель / дистрибьютор / поставщик-торговля / подрядчик / исполнитель услуг) с причинами и уверенностью.
Внешние API нейросетей не используются: только TF-IDF, правила и логистическая регрессия.

## Запуск

```bash
# 0. данные: CSV из архива организаторов -> C:\tenderhack\data\raw  (путь меняется через TH_DATA_DIR)
python -m app.etl.build_db            # CSV -> DuckDB, профили поставщиков        ~1 мин
python -m app.search.index            # TF-IDF индекс лотов                         ~5 мин
python -m app.search.okpd_index       # индекс позиций ТРУ для определения ОКПД2    ~3 мин
# обогащение (по желанию, всё кэшируется)
python -m app.etl.download <url реестра МСП> C:\tenderhack\data\ext\rmsp.zip
python -m app.etl.rmsp                # выгрузка реестра МСП -> parquet (СПб, ЛО + все поставщики датасета)
python -m app.enrich.rmsp_api 15000   # прогрев кэша онлайн-API реестра МСП для активных поставщиков

uvicorn app.main:app --port 8000      # http://127.0.0.1:8000
```

На Windows с включённым системным прокси Python-HTTPS падает с `SSLEOFError`; весь наш код ходит в сеть с `trust_env=False`.

## Как работает поиск

```
запрос -> очистка шума (№, 44-ФЗ, годы, районы, заказчики) -> леммы (pymorphy3) -> [модуль NLP команды: опечатки, синонимы]
       -> похожие лоты (TF-IDF, предмет + позиции ТРУ)
       -> ОКПД2 запроса (kNN по 1,15 млн позиций ТРУ)
       -> кандидаты: участники похожих лотов + поставщики с опытом по этим ОКПД2
       -> скоринг по объяснимым признакам -> обогащение (реестр МСП, ЕГРЮЛ) -> роль -> новые компании
```

| Признак | Вес | Смысл |
|---|---|---|
| Похожие закупки | 0.50 | сумма похожести лотов (победа ×1, участие ×0.5), штраф если ОКПД2 лота не совпал, затухание 1 год |
| Опыт по ОКПД2 | 0.25 | лоты/победы по предсказанным кодам ОКПД2 |
| Доля побед в категории | 0.20 | доля побед в похожих закупках Электронного магазина (по АИС ГЗ в данных только победители) |
| Свежесть | 0.07 | давность последней похожей закупки |
| СПб / ЛО | 0.05 | регион регистрации |
| Число заказчиков | 0.03 | сколько разных заказчиков в похожих закупках |

## Основной сценарий: «по данным закупки»

Вход — карточка закупки, как в АИС ГЗ: наименование, позиции спецификации (с ОКПД2), НМЦ, ИНН заказчика, площадка (ЭМ / АИС ГЗ),
признак «только для СМП». Три способа ввода: форма на сайте, **файл-шаблон** (Excel / CSV, одна строка = одна позиция,
`GET /api/template.xlsx`) с пакетной обработкой (`POST /api/batch`, выгрузка `GET /api/batch/{id}.xlsx`: листы
«Сводка», «Рекомендации», «Ошибки»), быстрый поиск по названию. Любое поле, кроме названия/позиций, может быть пустым.

Дополнительно к факторам поиска в этом сценарии учитываются:
- **история с заказчиком** — 57% победителей 2025 года уже выигрывали у того же заказчика раньше;
- **цена** — близость НМЦ к типичному размеру закупок поставщика;
- **площадка** — доля опыта поставщика на ЭМ / АИС ГЗ;
- **СМП** — закупка только для малого бизнеса: оставляем только компании из реестра МСП;
- **ОКПД2 из спецификации** берутся как есть, а не угадываются.

## Качество (офлайн-оценка)

Честный split по времени: история = 2024, запросы = карточки реальных закупок 2025 года, правильный ответ = фактический победитель.
Оценка воспроизводима: `python -m app.eval.procedure_eval`, 1000 закупок из фиксированного списка `tests/eval_lots.csv`.
Бейзлайны получают те же входные данные (заказчик и ОКПД2 из спецификации).

| Вариант | Победитель в топ-10 | 95%-интервал | MRR |
|---|---|---|---|
| **Наш алгоритм, карточка закупки** | **51.6%** | 48.6–54.7 | 0.314 |
| Бейзлайн «заказчик + ОКПД2» | 45.8% | 42.8–48.8 | 0.276 |
| Бейзлайн «топ по ОКПД2» | 33.4% | 30.6–36.3 | 0.161 |
| Наш алгоритм, только название (300 закупок) | 44.3% | 38.7–50.0 | 0.256 |

Прирост к сильному бейзлайну: +5.8 п.п. (95%-интервал +3.2…+8.4). По площадкам: ЭМ 56.5% против 52.1%, АИС ГЗ 46.2% против 38.9%.

Важное про данные: в Электронном магазине записаны все участники, а по АИС ГЗ — только победитель процедуры.
Поэтому доля побед и конкуренция считаются только по ЭМ, победы в АИС ГЗ показываются отдельно.
«Похожей» считается закупка с близким названием (косинус ≥ 0.35) и тем же ОКПД2 (коды сравниваются по префиксу).

Блок «Новые компании» проверен отдельно (`python -m app.eval.new_companies_eval`): новички — 12.2% победителей 2025 года;
блок в принципе может найти 29% из них (остальные — ИП или вне пула), в топ-10 попадает 1.1%, в топ-200 — 20%.
Подробности и ограничения — в [docs/METHOD.md](docs/METHOD.md), простыми словами — [docs/SIMPLE.md](docs/SIMPLE.md),
какие внешние источники проверены и почему часть не подошла — [docs/EXTERNAL_SOURCES.md](docs/EXTERNAL_SOURCES.md).

## Источники обогащения

| Источник | Что даёт | Как |
|---|---|---|
| Реестр МСП ФНС, открытые данные | название, ОКВЭД основной/доп., регион, категория, численность; пул для поиска новых: юрлица СПб/ЛО + производители и средние оптовики из других регионов | zip 2,1 ГБ -> parquet, индекс ОКВЭД -> компании |
| Реестр МСП, rmsp.nalog.ru | то же + телефон, email; поиск компаний по ОКВЭД и региону | онлайн, кэш SQLite |
| ЕГРЮЛ, egrul.nalog.ru | название, ОГРН, руководитель, ликвидация | онлайн, кэш SQLite |
| РНП, zakupki.gov.ru (ЕИС) | записи реестра недобросовестных поставщиков: действующие и исключённые | онлайн, кэш SQLite; действующая запись — красный флаг и балл ×0.5 |

## Модуль NLP (команда словарей)

`nlp/query.py` подключён как основной обработчик запроса (`app/core/text.py`, запасной вариант — встроенная очистка):
раскладка, опечатки, бренды, тип закупки (товар/работа/услуга), выделение предмета закупки, синонимы и аббревиатуры
с весами. Веса используются как относительная важность термина (`вес / макс. вес`) и умножаются на IDF индекса —
синоним никогда не весит больше исходного слова. Объяснения модуля (`explain`) показываются в интерфейсе.

## Масштабирование

- **Данные.** Индексы строятся офлайн за ~5 минут на 600 тыс. закупок и линейно растут с объёмом; в памяти — разреженные
  матрицы и целочисленные массивы (~1.6 ГБ на весь датасет). Новые закупки добавляются пересборкой по расписанию.
- **Нагрузка.** Сервис не хранит состояние между запросами (кроме кэша результатов пакета), поэтому масштабируется
  горизонтально: несколько экземпляров за балансировщиком, индексы только на чтение. Запрос — 0.2–2 с на 2 ядрах.
- **Другие регионы и площадки.** Вход — три таблицы (извещения, позиции, заявки) в формате выгрузки АИС ГЗ;
  для другого региона меняются только файлы данных и коды регионов в `app/config.py`.
- **Источники обогащения** подключаются как отдельные модули `app/enrich/*` с общим приёмом «кэш + онлайн по ИНН»;
  недоступность источника не ломает поиск — поле просто остаётся пустым.
- **Узкие места.** Онлайн-реестры ФНС и ЕИС ограничивают частоту запросов, поэтому всё кэшируется и прогревается заранее;
  при росте данных на порядок TF-IDF стоит заменить на поисковый движок (OpenSearch) с теми же признаками.

## Структура

```
app/
  config.py          пути (DATA_DIR вне OneDrive)
  etl/               build_db (CSV -> DuckDB), rmsp (реестр МСП), download (докачка)
  core/text.py       токенизация, лемматизация, стоп-слова, очистка шума
  search/            index, okpd_index, engine (поиск + скоринг + объяснения)
  enrich/            rmsp_api, egrul, rnp (недобросовестные поставщики), roles (классификация ролей),
                     store (обогащение + новые компании)
  batch.py           шаблон закупок: разбор CSV/Excel, пакетная обработка, выгрузка в Excel
  eval/              evaluate, train_weights, procedure_eval (оценка сценария «по данным закупки»)
  main.py            FastAPI
frontend/            index.html + app.js + style.css (без сборки)
nlp/, data/nlp/      модуль разбора запроса: опечатки, ключевые слова, синонимы
scripts/, tests/     сборка словарей, генератор тестовых закупок, тесты
```
