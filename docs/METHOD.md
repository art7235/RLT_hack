# Как сервис подбирает поставщиков: сценарий и алгоритм

Документ описывает, что делает пользователь, что происходит внутри и почему сделано именно так.
Все числа и параметры соответствуют текущему коду (`app/search/engine.py`).

## 1. Коротко

Это не нейросеть и не «чёрный ящик». Это **поиск по истории закупок с объяснимым скорингом**:

1. по данным закупки находим похожие прошлые закупки АИС ГЗ и Электронного магазина;
2. смотрим, кто в них участвовал и побеждал;
3. каждому поставщику считаем балл как взвешенную сумму понятных факторов;
4. проверяем поставщика по государственным реестрам и определяем его роль на рынке;
5. отдельно находим новые компании, которых в истории нет.

Внешние API нейросетей не используются (условие хакатона). Используются: TF-IDF (классический текстовый поиск),
морфологический анализатор pymorphy3, словари синонимов и линейная модель для проверки весов.

## 2. Сценарий работы

**Пользователь** — заказчик (школа, больница, администрация), который готовит закупку и хочет понять,
кто реально может её выполнить.

**Что он вводит** — данные закупки, как в карточке АИС ГЗ:

| Поле | Обязательно | Зачем |
|---|---|---|
| Наименование закупки | да (или позиции) | главный источник смысла |
| Позиции спецификации | да (или название) | уточняют предмет, по ним определяется ОКПД2 |
| Коды ОКПД2 позиций | нет | если даны — берём как есть, не угадываем |
| НМЦ | нет | подходит ли поставщику масштаб закупки |
| ИНН заказчика | нет | кто уже работал с этим заказчиком |
| Площадка (ЭМ / АИС ГЗ) | нет | опыт поставщика именно на этой площадке |
| Только для СМП | нет | оставляем только малый бизнес |

**Три способа ввода:**

1. **Карточка закупки** — форма на сайте, одна закупка.
2. **Файл-шаблон** (Excel / CSV) — много закупок сразу. Одна строка — одна позиция, у позиций одной закупки
   общий номер. Подходят и выгрузки с названиями колонок как в АИС ГЗ. На выходе сводная таблица и Excel
   с листами «Сводка», «Рекомендации», «Ошибки».
3. **Быстрый поиск** — одна строка с названием, когда других данных нет.

**Что он получает** по каждой закупке:

- рейтинг поставщиков из истории закупок: балл 0–100, статус, роль, причины рекомендации,
  разбивка балла по факторам, примеры похожих закупок, контакты, отметка о реестре недобросовестных;
- отдельный список **новых компаний**, которые в закупках не участвовали, но по виду деятельности подходят;
- блок «как система поняла закупку»: исправленные опечатки, ключевые слова, тип, коды ОКПД2;
- предупреждение, если точных совпадений в истории мало.

## 3. Данные

Три таблицы из АИС ГЗ за 2024–2025 годы:

| Таблица | Объём | Что в ней |
|---|---|---|
| Извещения | 604 тыс. закупок | название, НМЦ, заказчик, площадка, признак СМП, дата |
| ТРУ | 3 млн позиций | название позиции и её код ОКПД2 |
| Поставщики | 1 млн заявок | кто подал заявку на какую закупку и победил ли |

Одна процедура = один лот. В данных только ИНН поставщиков, без названий — поэтому обогащение обязательно.

Три факта о данных, которые определили алгоритм:

- **В данных две площадки с разной полнотой.** В Электронном магазине (ЭМ) записаны все участники: в среднем
  2,7 на закупку, побеждает 36% заявок. По АИС ГЗ (процедуры с номером извещения ЕИС и малые закупки) в выгрузке
  есть **только победитель**: ровно 1 участник на закупку, доля побед 100%. Это не «закупки без конкуренции» —
  проигравшие просто не выгружены. Поэтому долю побед и конкуренцию считаем только по ЭМ, а победы в АИС ГЗ
  показываем отдельно, с оговоркой.
- **57% победителей 2025 года уже выигрывали у того же заказчика раньше.** История с заказчиком — сильный сигнал.
- **Коды ОКПД2 записаны с разной глубиной.** Около 5% позиций закодированы неполно (у лекарств 29% — просто `21.20`),
  поэтому коды сравниваются по префиксу: `21.20` и `21.20.10` считаются одним товаром.

## 4. Алгоритм по шагам

Сквозной пример: быстрый поиск **«поставка ноутбуков»**.

### Шаг 1. Разбор текста

Модуль `nlp/` (сделан командой словарей):

- исправляет опечатки и неверную раскладку: «ноутбк леново» → «ноутбук lenovo», «ghbynth» → «принтер»;
- отбрасывает шум: «для нужд ГБОУ школа № 548», ссылки на 44-ФЗ, номера, даты;
- определяет тип закупки по словам-действиям: «поставка» → товар, «оказание услуг», «ремонт» → услуга/работа;
- приводит слова к начальной форме: «ноутбуков» → «ноутбук»;
- добавляет синонимы с меньшим весом: «лэптоп», «портативный компьютер».

Поверх этого движок:

- не берёт «более общие» расширения («перчатки» → «хозтовары») и голые числа («15.6») — они размывают выдачу;
- возвращает содержательные слова, которые модуль отбросил («обучающихся» отличает школьное питание от больничного).

Каждое слово получает вес: слово из запроса — 1, синоним — меньше.

### Шаг 2. Два поисковых индекса (TF-IDF)

TF-IDF — способ взвешивать слова: редкое слово («ноутбук») важнее частого («техника»).
Похожесть запроса и документа — косинус между их векторами, число от 0 до 1.

| Индекс | Документ | Зачем |
|---|---|---|
| По закупкам | название закупки + названия её позиций (позиции с весом ×2: они чище) | найти похожие закупки |
| По позициям | 1,15 млн уникальных пар «название позиции → код ОКПД2» | определить ОКПД2 запроса |

Индексы строятся заранее (~5 минут), запрос обрабатывается за 0,2–2 секунды.

### Шаг 3. Код ОКПД2

- **Если коды есть в спецификации** — берём их как есть. Доля кода = доля позиций с ним.
- **Если нет** — голосуют два источника поровну: 300 ближайших по названию позиций (вес
  `похожесть³ × log(1 + частота)`) и 300 самых похожих закупок целиком (вес `похожесть²`).
  Одних позиций мало: «питание обучающихся на соревнованиях» встречается в десятке вариантов и тянет
  к спортивным услугам, а закупки показывают, что чаще всего это «услуги столовых».
  Коды берутся на уровне вида продукции (`26.20.11`).
- **Тип закупки** усиливает коды нужного раздела в 4 раза (товары — классы 01–32, работы и услуги — 33+)
  и, если лидер совпал с типом, отбрасывает коды другого типа. Иначе «поставка молока» находила бы
  «лабораторные исследования молока».

Пример: «поставка ноутбуков» → `26.20.11` «Компьютеры портативные массой не более 10 кг».
Названия кодов — из официального классификатора ОК 034-2014.

### Шаг 4. Кандидаты

Три источника:

1. участники до 8000 закупок, у которых есть общие слова с запросом;
2. до 500 поставщиков с наибольшим опытом по найденным кодам ОКПД2 (даже без совпадения по словам);
3. поставщики, которые работали с этим заказчиком по этой категории (если заказчик указан).

Если закупка «только для СМП» — оставляем только компании из реестра МСП.

### Шаг 5. Что считается «похожей закупкой»

Это ключевое определение. **Похожая закупка — та, у которой одновременно:**

- близкое название: похожесть ≥ 0,35;
- тот же код ОКПД2, что у запроса.

Только по таким закупкам считаются счётчики «участвовал / победил», число заказчиков, статус и примеры.
Закупки с парой общих слов, но другим предметом, в счётчики не попадают — они лишь слабо влияют на балл
(с весом `похожесть² × 0,25`).

### Шаг 6. Факторы

Каждый фактор — число от 0 до 1.

| Фактор | Вес | Как считается |
|---|---|---|
| **Похожие закупки** | 0,50 | сумма по закупкам с общими словами: `похожесть² × (1, если ОКПД2 совпал, иначе 0,25) × (1 за победу, 0,5 за участие) × 0,5^(возраст в годах)`; затем логарифм и нормировка на лучшего кандидата |
| **Опыт по ОКПД2** | 0,25 | по найденным кодам: `доля кода × (победы + 0,5 × участия без победы)`; логарифм и нормировка |
| **Доля побед в категории (ЭМ)** | 0,20 | `(победы + 1) / (участия + 3)` в похожих закупках **Электронного магазина** — сглажено, чтобы 1 победа из 1 не давала 100%. Если у поставщика только победы в АИС ГЗ — нейтральное значение 0,35 (средняя доля побед в ЭМ): о конкуренции там ничего не известно |
| **Работал с заказчиком (эта категория)** | 0,20 | закупки этого заказчика с тем же классом ОКПД2, логарифмическая шкала |
| **Свежесть** | 0,07 | `0,5^(дней с последней похожей закупки / 365)` |
| **Работал с заказчиком (вообще)** | 0,05 | любые закупки этого заказчика, логарифмическая шкала |
| **Подходит по цене** | 0,05 | близость НМЦ к медианной цене закупок поставщика (на порядок больше или меньше — около нуля) |
| **СПб / ЛО** | 0,05 | 1 — стоит на учёте в СПб, 0,5 — в Ленобласти (у юрлиц — по КПП в заявках, у ИП — по ИНН: в поле КПП у них мусор) |
| **Специализация** | 0,05 | доля закупок поставщика, приходящаяся на ОКПД2 этой закупки |
| **Заказчиков в похожих** | 0,03 | число разных заказчиков в похожих закупках / 10, не больше 1 |
| **Опыт на площадке** | 0,03 | доля закупок поставщика на ЭМ или АИС ГЗ |

Факторы про заказчика, цену и площадку участвуют, только если соответствующее поле заполнено.

### Шаг 7. Итоговый балл

```
балл = 100 × уверенность × Σ(вес × фактор) / Σ(веса активных факторов)
```

Веса нормируются по тем факторам, для которых есть данные: если заказчик не указан, его отсутствие
не занижает балл. При полностью заполненной карточке доли такие: предмет закупки (похожие закупки + ОКПД2) — 51%,
доля побед — 13,5%, заказчик — 17%, остальное — около 19%.

Пример, «поставка ноутбуков», ООО КОМПЬЮТЕРНЫЕ СИСТЕМЫ — балл 82,5:

| Фактор | Вклад |
|---|---|
| Похожие закупки | +42,4 |
| Опыт по ОКПД2 | +21,3 |
| Свежесть опыта | +6,1 |
| Доля побед в категории (ЭМ) | +5,2 |
| СПб / ЛО | +4,3 |
| Заказчиков в похожих закупках | +2,6 |
| Специализация на категории | +0,5 |

Сумма вкладов равна баллу — объяснение и ранжирование не расходятся.

### Шаг 8. Уверенность подбора

Балл считается относительно лучшего кандидата, поэтому без поправки даже случайное совпадение выглядело бы
как 90+. Поэтому у запроса есть абсолютная уверенность:

| Уровень | Условие | Что происходит |
|---|---|---|
| Высокая | 30+ похожих закупок, все ключевые слова в них встречаются | балл как есть |
| Средняя | похожих 10–29 или какое-то ключевое слово не встречается | балл ×0,85, предупреждение с этим словом |
| Низкая | похожих меньше 10 | балл ×0,6, статус «Близкий профиль», красное предупреждение |

Примеры: «корм котов» — средняя («не встречается: кот»); «попугаи» — низкая (2 похожих закупки, и те про корм).

### Шаг 9. Статус

| Статус | Условие |
|---|---|
| Проверенный | ≥ 3 побед в похожих закупках; если есть 3+ участия в ЭМ — доля побед в них ≥ 25% (для АИС ГЗ доля не проверяется: проигравшие не выгружены) |
| С опытом | ≥ 1 победы в похожих или ≥ 3 побед по тем же кодам ОКПД2 |
| Участник | участвовал в похожих закупках ЭМ, но не побеждал (в АИС ГЗ такой статус невозможен) |
| Профильный | есть только опыт по ОКПД2 или закупки с общими словами |
| Близкий профиль | уверенность подбора низкая |
| Новый | компания вне истории закупок |

Пример: у «Ремоборудования» 8 побед из 256 участий в ЭМ (3%) — это «С опытом», а не «Проверенный».

### Шаг 10. Объяснения

Причины в карточке строятся из тех же чисел, что и балл:

- «Похожие закупки в Электронном магазине: участвовал в 162, победил в 48, из них при 2+ участниках — 48»;
- «Победитель 6 похожих процедур АИС ГЗ (по АИС ГЗ в данных есть только победители — другие участники не раскрываются)»;
- «Уже выигрывал у этого заказчика закупки этой категории: 1»;
- «Опыт по ОКПД2 26.20.11 «Компьютеры портативные…»: 344 закупки, 123 победы»;
- «Профильный поставщик: 64% его закупок — в этой категории» или «Универсальный поставщик: … 3%».

Примеры закупок подбираются так, чтобы подтверждать причины: сначала закупка этого же заказчика,
затем победы, затем самые похожие.

### Шаг 11. Проверка по реестрам

После ранжирования к каждому поставщику подтягиваются данные:

| Источник | Что даёт |
|---|---|
| Реестр МСП ФНС (полная выгрузка, 490 тыс. компаний СПб и ЛО) | название, основной и дополнительные ОКВЭД, категория, численность |
| Реестр МСП, онлайн | телефон и email (если компания их указала) |
| ЕГРЮЛ | название, руководитель, ликвидация — для крупных компаний вне реестра МСП |
| РНП (ЕИС) | записи реестра недобросовестных поставщиков |

Действующая запись в РНП — красный флаг, балл снижается вдвое, поставщик уходит вниз списка.

### Шаг 12. Роль на рынке

Роль определяется правилами с баллами за каждый признак:

- основной ОКВЭД: 01–32 — производитель, 33 — услуги ремонта, 41–43 — подрядчик,
  45/46 — дистрибьютор (оптовая торговля), 47 — поставщик (розница), остальное — услуги;
- дополнительные ОКВЭД — в пользу той роли, к которой относится большинство;
- слова в названии: «завод», «фабрика» → производитель; «торговый дом», «снаб» → дистрибьютор;
- поставки из 8+ разных классов ОКПД2 → признак торгового посредника;
- если ОКВЭД неизвестен — по классу ОКПД2, в котором поставщик чаще всего побеждает.

Уверенность показывается словами (высокая / средняя / низкая) — это оценка согласованности признаков,
а не вероятность. Для «дистрибьютора» честно указано: роль определена по виду деятельности,
партнёрство с производителями не проверялось. Если есть признаки второй роли — она тоже названа.

## 5. Новые компании

Отдельная вкладка: компании из реестра МСП, которых **нет в истории закупок** (198 тыс. юрлиц в пуле):

- все юрлица Санкт-Петербурга и Ленинградской области;
- из остальных регионов — производители (ОКВЭД 10–32, малые и средние предприятия) и средние оптовики, 31 тыс. компаний.

Иногородние показываются только для закупок **товаров** и занимают не больше 40% списка; для услуг и работ
остаются местные компании: питание или охрану из другого региона не закажешь.

**Какие виды деятельности ищем** по коду ОКПД2 закупки:

1. ОКВЭД того же класса (`26.20` продукция ↔ `26.20` производство) — классификаторы согласованы на этом уровне;
2. ОКВЭД, типичные для победителей закупок этого класса. Связка выучена на датасете:
   например, 34% победителей закупок по `26.20` имеют ОКВЭД `46.51` (оптовая торговля компьютерами).
   Так находятся оптовики, которых нельзя найти прямым совпадением кодов.

**Балл новой компании** — абсолютный, максимум 80 (без истории закупок 100 не бывает):

| Составляющая | Баллы |
|---|---|
| Вид деятельности совпадает с закупкой (основной ОКВЭД — полный вес, дополнительный — 0,4) | до 50 |
| Размер компании (логарифм числа сотрудников) | до 15 |
| Стаж в реестре МСП | до 5 |
| Санкт-Петербург / ЛО (у иногородних — 0) | до 5 |
| Есть контакты в реестре | до 5 |

Не больше 60% выдачи с одним ОКВЭД — чтобы были и производители, и оптовики.

**Проверка на данных** (`app/eval/new_companies_eval.py`). Берём победителей 2025 года, которых не было
в закупках 2024 года, и смотрим, нашёл бы их блок, работай он в конце 2024-го:

- новички — 12,2% победителей 2025 года (32 тыс. закупок);
- из них 52% — индивидуальные предприниматели (в пул входят только юрлица), 19% нет в пуле
  (крупные компании или иногородние не из выгрузки); блок в принципе может найти оставшиеся 29%;
- среди этих 29% в первую десятку попадает 1,1%, в первые 200 — 20%:
  под одну закупку подходит в среднем 47 тыс. компаний, и по одному ОКВЭД их не различить.
- добавление иногородних производителей эти цифры не изменило (было 1,3% и 21%): оно нужно не для угадывания
  новичков, а чтобы заказчик видел производителей товара, а не только местных посредников.

Вывод: блок расширяет круг кандидатов по виду деятельности, но не предсказывает, кто именно придёт на торги.

## 6. Как проверено качество

**Проверка «назад в будущее».** Системе доступны участия и победы только за 2024 год (словарь слов общий — независимая проверка
показала, что это не завышает результат). Ей дают карточки реальных закупок 2025 года
без участников и смотрят, попал ли фактический победитель в первую десятку.

Оценка воспроизводима: 1000 закупок, список зафиксирован в `tests/eval_lots.csv` (отбор по хэшу номера лота).
Сравнение — с бейзлайнами, у которых **те же входные данные** (заказчик и ОКПД2 из спецификации).

| Вариант | Победитель в топ-10 | 95%-интервал | MRR |
|---|---|---|---|
| **Наш алгоритм, карточка закупки** | **51,6%** | 48,6–54,7 | 0,314 |
| Бейзлайн «заказчик + ОКПД2»: кто выигрывал у этого заказчика в этом классе, затем топ по коду | 45,8% | 42,8–48,8 | 0,276 |
| Бейзлайн «топ по ОКПД2» | 33,4% | 30,6–36,3 | 0,161 |
| Наш алгоритм, только название (300 закупок) | 44,3% | 38,7–50,0 | 0,256 |

Прирост к сильному бейзлайну — **+5,8 п.п. (95%-интервал от +3,2 до +8,4)**: выигрыш статистически значим.
По площадкам: ЭМ — 56,5% против 52,1%, АИС ГЗ — 46,2% против 38,9%.

У 12% победителей 2025 года нет истории в 2024-м — по прошлым закупкам их найти нельзя в принципе.

**Как выбирались веса.** Сначала по смыслу, затем проверка линейной моделью (логистическая регрессия),
которую учили угадывать победителя. Она отдаёт связи с заказчиком 39% веса, но на отложенной выборке
не даёт выигрыша перед весами, где заказчик занимает около 17% балла. Оставлены сбалансированные веса:
то же качество без закрепления сложившихся связей. Без учёта заказчика совсем качество заметно ниже.
(Сравнение весов делалось на 200 закупках, где различия в 1–2 п.п. неразличимы; итоговые цифры выше — на 1000.)

## 7. Почему именно такой подход

- **Объяснимость.** Линейная сумма факторов позволяет показать вклад каждого. У нейросети так не получится.
- **Запрет на внешние API нейросетей.** Всё работает локально, без видеокарты, на сервере с 4 ГБ памяти.
- **Данные сами содержат ответ.** 1 млн заявок — это прямое знание «кто что поставляет»; сложная модель
  поверх него дала бы немного, а объяснимость потеряла бы.
- **Скорость.** Индексы строятся за 5 минут, запрос — доли секунды.

## 8. Ограничения

- Поиск по словам, а не по смыслу: синонимы покрываются словарём, но не полностью.
- Если предмета закупки нет в истории (попугаи), система покажет ближайшее и предупредит — других данных нет.
- Новые компании — только малый и средний бизнес: крупных в реестре МСП нет.
- Роль определяется по заявленному виду деятельности, реальное партнёрство с производителями не проверяется.
- Блок «Новые компании» слабо различает кандидатов: будущий победитель-новичок попадает в топ-10 в 1,3% случаев
  (см. раздел 5). В пул не входят ИП, а именно они — половина реальных новичков.
- Крупных производителей в «Новых компаниях» нет: есть малые и средние, в том числе из других регионов.
  Источники с видом деятельности крупных компаний закрыты или платные — разбор в
  [EXTERNAL_SOURCES.md](EXTERNAL_SOURCES.md).
- По АИС ГЗ в данных нет проигравших участников, и восстановить их из ЕИС нельзя: в протоколах участники
  обезличены (см. [EXTERNAL_SOURCES.md](EXTERNAL_SOURCES.md)). Конкурентоспособность таких поставщиков не оценивается.
- Регион юрлица определяется по КПП в заявках; у компании с филиалом это может быть регион филиала.
- Контакты есть только у тех, кто сам указал их в реестре МСП.
